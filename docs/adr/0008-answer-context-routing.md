# ADR-0008 · 回答质量语义增强：选型问法护栏 + 回答多轮上下文

- 状态：Proposed → Accepted（人类 2026-09-20 授权"一步一步推进"）
- 关联：outputs/AI引导与回答优化方案-2026-09-20.md §五（实测诊断 B3/B4）· 01-port-spec §6 · 03-api-spec
- 决策人：人类授权执行席（Hy4）落地

## 背景

实测（SSE 直连 + 运营看板）发现两类语义缺陷，均属"回答不太聪明"的根因：

1. **B3 路由错位**：「无油泵和旋片泵怎么选？」是**类型级选型咨询**，意图分类器判为
   `product_flow` → 用整句搜产品目录 → 零结果 → 回答"暂未找到匹配产品"。
   而站内知识库本有选型指南语料（recall@5=0.900），应走 `knowledge_flow` 让 RAG 回答。
2. **B4 无记性**：`knowledge_flow` 的回答 LLM 只见「当前问题 + 检索资料」，
   对话历史只进了意图提取（且截断 80 字/条）。多轮指代（"它多少钱""第一个呢"）断裂。

业界锚点（Sphere/SurePrompts 企业 RAG 六件套；Temporal AI Cookbook 确定性护栏）：
LLM 管意图理解，可复现的系统性误判用**确定性护栏**修正；回答生成必须带多轮上下文。

## 决策

### D1 选型问法护栏（routing_guards 扩展，家族第三个 guard）

```
selection_over_search:
  route ∈ {product_flow, selection_flow, compare_flow}
  AND 消息命中选型咨询标记（怎么选/区别/哪个好/优缺点/有什么区别/选哪个）
  AND 消息不含两个产品编号（真正的产品对比走 compare_flow，不拦截）
  → route = knowledge_flow（RAG 以选型指南语料作答），记录 route_guard 审计轨迹
```

窄口径：只在"问法明确是类型级选型对比"时触发；带两个具体产品 ID 的对比不受影响；
不含标记词的路由不受影响。

### D2 回答多轮上下文注入

`knowledge_flow` 的 `answer_user` 在「问题+资料」之前注入**最近 4 轮**对话
（每条截断 120 字符，含角色前缀），格式与意图提取的历史注入一致。
作用域仅 knowledge_flow（唯一 LLM 自由作答路径）；模板路径零改动、零 token 增量。

### D3 意图提取历史扩容

`_understand_node` 历史条目截断 80 → 120 字符（仍取最近 6 条）。
理由：80 字会截断含关键工况参数的长问句，导致指代消解失败；120 字成本增量可忽略。

## 后果

- +正：选型类问题获得 RAG 选型建议而非"暂未找到"；多轮追问可解析指代。
- −负：knowledge_flow 每轮 prompt 增加约 300~500 token（4×120 字符 ×2 条消息）；
  路由护栏属硬规则，若标记词表过宽可能误拦（以窄口径 + 审计轨迹 + eval 回归控制）。
- 评测：run_eval B/C/D 全绿为合入门禁；新增护栏单测（命中/不命中/双 ID 不拦截）。

## 权衡备选

- 仅改意图提示词 few-shot（否决：该误判具模型方差性，提示词不稳定，2026-09-16 同类教训
  已证明需确定性护栏）。
- 回答历史全量注入（否决：token 成本与注入攻击面增大，4 轮 120 字符够解析近指代）。
